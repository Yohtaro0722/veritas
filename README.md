# Veritas — マップ連動 顧客管理アプリ（人材派遣ローラー営業向け）

地図起点の顧客管理ツール。歩きながらビルをタップすると、そのビルのテナント（入居企業）
一覧が出て、過去の活動履歴・契約状況を確認でき、**次に攻めるべき先が自動で浮かび上がる**。

> v0.1（MVP / 個人利用フェーズ）。完全ローカル・サーバ不要・通信ゼロで現場稼働。

## 設計の核

- データの主キーは **建物（Building）**。マップ重視を貫く。
- 「見込みリストの自動生成」= AIの予測ではなく、現場で入れた **4つの事実フラグをルールで仕分けて優先度を吐く**こと（完全オフラインで決定論的）。
- テナント情報は **自分で撮った案内板を起点に手動登録**する。

## 2モード設計

| モード | 状況 | できること |
|---|---|---|
| **準備モード** | オンライン・机 | エリアの地図タイル＋建物ポリゴンを事前DL、住所ジオコーディング、法人番号補完、バックアップ |
| **現場モード** | オフライン・歩行 | 地図/現在地、ビルタップ→テナント一覧、案内板撮影＋手入力、4フラグ更新、活動ログ、優先度表示 |

すべて IndexedDB ＋ ローカル写真保存で完結。通信ゼロで動作する（事前DL済みエリア内）。

## 4フラグ（§4.1）

| フラグ | 値 | 性質 |
|---|---|---|
| 派遣利用有無 | 有 / 無 / **不明** | 唯一の探索対象。ローラーの主目的 |
| 過去受注有無 | 有 / 無 | 自社記録で確定 |
| 基本契約有無 | 有 / 無 | 自社側で確定 |
| 担当接触有無 | 有 / 無 | 自分が動いたか・確定 |

## 優先度の自動仕分け（§5.4）

| 派遣 | 受注 | 契約 | 接触 | 状態 |
|---|---|---|---|---|
| 有 | 無 | 無 | 無 | **最優先・新規開拓** |
| 有 | 無 | 無 | 有 | 育成中 |
| 有 | 有 | 有 | 有 | 既存・深耕／追加提案 |
| 有 | 有 | 無 | 有 | 正常フロー（警告色なし） |
| 不明 | - | - | 無 | **未開拓** |
| 無 | - | - | - | 低優先 |

実装は `src/lib/priority.ts`。テストは `src/lib/priority.test.ts`。

## 技術スタック（全て無料・APIキー不要を優先）

- Vite + React + TypeScript
- 地図描画: Leaflet + react-leaflet
- 地図タイル: 地理院タイル（国土地理院）
- 建物ポリゴン: Overpass API（OSM）
- ローカルDB: Dexie.js（IndexedDB）
- オフライン/PWA: vite-plugin-pwa（Workbox）
- 会社名寄せ: 国税庁 法人番号システム Web-API（任意・要アプリID）
- 住所→緯度経度: 国土地理院 ジオコーディングAPI

### 法人番号API（任意）

`.env.example` を `.env` にコピーし、`VITE_HOUJIN_APP_ID` を設定すると、テナント詳細で
正式名称・法人番号の補完が有効になる（未設定でもアプリは動作）。

## 使い方（現場）

1. **準備モード**で対象エリアを住所検索 → 半径を選び「このエリアをDL」（地図＋建物をキャッシュ）。
2. 現場では**地図**でビルをタップ → ビル詳細へ。ポリゴン未取得のビルは「ビルを追加」で地図上に手置き。
3. **案内板を撮影** → 見ながら**テナントを追加**（社名・階）。
4. テナント詳細で**4フラグ**を入力。活動を記録すると接触=有に、受注を追加すると受注=有に自動同期。
5. **今日攻める**タブに優先度順で並ぶ。

## オフライン/PWA

- HTTPS 必須（PWA / Service Worker）。Vercel 等へデプロイして利用。
- 地理院タイルは閲覧/DL時に Workbox が `gsi-tiles` キャッシュへ格納。事前DL済み範囲はオフラインで表示可能。
- 実機でのオフライン挙動（足の検証）は要実地確認（§9-10）。

## データの扱い（§6）

- 全データ・写真は端末内（IndexedDB）。第三者へ送信しない。
- バックアップ/復元は準備モードから手動・ローカルファイル（JSON）のみ。
